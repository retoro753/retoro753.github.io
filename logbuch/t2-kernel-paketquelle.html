Stand: 17.11.2026. Die Sache ist noch nicht abschließend geklärt. Ich ergänze diese Notiz, sobald es Neues gibt.

> Kurz gesagt

Beim Update von Omarchy auf meinem T2-MacBook ist mir im Namen des Kernels eine politische Beleidigung gegen DHH, den Gründer von Omarchy, aufgefallen. Das Paket stammte aus einer fremden Paketquelle, die ohne Signaturprüfung eingebunden war. Die Botschaft selbst ist nicht das eigentliche Problem. Das Problem ist, dass jemand unbemerkt einen veränderten Kernel ausliefern konnte.

> Was passiert ist

  • Betroffen ist das Paket linux-t2 in Version 7.3.4.arch1-2 aus der Paketquelle [arch-mact2]. Diese Quelle wird nicht von Omarchy selbst betrieben.
  • Das Paket wurde am 14.11.2026 von einem unbekannten Ersteller („Unknown Packager“) gebaut.
  • Die Beleidigung steht im Versionsnamen des Kernels. Sie erscheint über jeder Konsolen-Anmeldung und bei uname -r.
  • Die Paketquelle war mit SigLevel = Never eingebunden. Das System hat also nicht geprüft, von wem die Pakete stammen.
  • Omarchy hat am 16.11.2026 reagiert und bezieht die T2-Pakete seitdem aus der eigenen Quelle [omarchy].

> Was noch offen ist

  • Ob nur der Name geändert wurde oder auch der Code des Kernels, ist nicht belegt. Bisher hat niemand den Code mit dem Original verglichen.
  • Omarchy hat sich zu dem GitHub-Eintrag noch nicht geäußert.
  • Aus derselben Quelle kamen auch andere T2-Pakete, etwa für Audio, WLAN-Firmware und die Lüftersteuerung.

> Warum das wichtig ist

Wer eine Paketquelle betreibt, kann jederzeit neue Versionen mit beliebigem Inhalt veröffentlichen. Das ist bei jeder Quelle so: Man vertraut immer den Menschen dahinter. Signaturen beweisen wenigstens, von wem ein Paket kommt. Fehlt die Prüfung, kann auch jemand anderes Pakete unterschieben.

Diesmal war es eine Beleidigung im Namen. Genauso hätte Schadcode in einem Kernel stecken können, und der Kernel hat volle Kontrolle über das ganze System. Solche Angriffe über die Lieferkette nennt man Supply-Chain-Angriffe.

> So prüfst du dein System

Welcher Kernel läuft gerade?

uname -r

Ist die fremde Quelle noch eingetragen, und wie ist die Signaturprüfung eingestellt?

grep -A3 "arch-mact2" /etc/pacman.conf

Laut dem GitHub-Eintrag ersetzt ein Update über die Quelle [omarchy] das betroffene Paket. Vorher unbedingt ein Backup machen: Ein Kernelwechsel auf einem T2-Mac kann schiefgehen.

As of 2026-11-17. This hasn't been fully resolved yet. I'll update this note as soon as there's news.

> In short

While updating Omarchy on my T2 MacBook, I noticed a political insult against DHH, the founder of Omarchy, in the kernel's name. The package came from a third-party package source that was set up without signature checking. The message itself isn't the real problem. The problem is that someone could ship a modified kernel without anyone noticing.

> What happened

  • The affected package is linux-t2 version 7.3.4.arch1-2 from the [arch-mact2] package source. That source is not run by Omarchy itself.
  • The package was built on 2026-11-14 by an unknown builder ("Unknown Packager").
  • The insult is in the kernel's version name. It shows up above every console login and in uname -r.
  • The package source was configured with SigLevel = Never, so the system never checked who the packages came from.
  • Omarchy responded on 2026-11-16 and now takes the T2 packages from its own [omarchy] source.

> What's still unclear

  • Whether only the name was changed or the kernel code as well is not established. So far nobody has compared the code against the original.
  • Omarchy hasn't commented on the GitHub issue yet.
  • Other T2 packages came from the same source too, for example for audio, Wi-Fi firmware and fan control.

> Why this matters

Whoever runs a package source can publish new versions with any content at any time. That's true for every source: you always trust the people behind it. Signatures at least prove who a package comes from. Without that check, someone else can slip packages in as well.

This time it was an insult in a name. It could just as well have been malware in a kernel, and the kernel has full control over the entire system. Attacks like this through the delivery chain are called supply-chain attacks.

> How to check your system

Which kernel is running right now?

uname -r

Is the third-party source still configured, and how is signature checking set?

grep -A3 "arch-mact2" /etc/pacman.conf

According to the GitHub issue, an update from the [omarchy] source replaces the affected package. Make a backup first: swapping the kernel on a T2 Mac can go wrong.
