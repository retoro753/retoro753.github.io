> Kurz gesagt

Tailcat ist ein Kommandozeilen-Tool von Tailscale, das zwei Rechner in Sekunden über einen verschlüsselten Tunnel verbindet. Damit kann man sich per SSH einloggen, Daten übertragen oder Ports weiterleiten. Man braucht dafür weder ein Konto noch Root-Rechte, und es funktioniert nicht nur im Heimnetz, sondern auch über das Internet.

> So funktioniert es

  • Auf dem Rechner, den man erreichen will, startet man Tailcat. Es zeigt eine Tailcat-Adresse an, eine lange Zeichenkette, die mit tc beginnt.
  • Diese Adresse gibt man dem anderen Rechner. Damit baut Tailcat den Tunnel auf.
  • Verschlüsselt wird mit WireGuard, demselben Protokoll, das auch Tailscale nutzt.
  • Wenn möglich, verbinden sich die Rechner direkt. Klappt das nicht, etwa wegen Router oder Firewall, läuft die Verbindung über ein Relais von Tailscale.
  • Tailcat läuft komplett als normales Programm: kein Root, keine Änderungen an Netzwerk-Einstellungen oder DNS.

> Was man damit machen kann

Text oder Daten schicken:

# Rechner A (zeigt die Adresse an)
tailcat

# Rechner B
echo hallo | tailcat [ADRESSE]

Per SSH einloggen:

# Rechner A
tailcat --serve=no-auth-ssh

# Rechner B
tailcat ssh [ADRESSE]

Einen Port weiterleiten, zum Beispiel einen lokalen Webserver:

# Rechner A
tailcat --serve=8080

# Rechner B
tailcat [ADRESSE] 8080

Außerdem gibt es einen SOCKS5-Proxy und einen SFTP-Server für Dateiübertragungen über den Tunnel.

> Tailcat oder Tailscale?

Tailcat ist für kurze, spontane Verbindungen gedacht: mal schnell per SSH auf einen Rechner, eine Datei rüberschieben, einen Dienst kurz freigeben. Wer seine Geräte dauerhaft in einem privaten Netz verbinden will, ist mit Tailscale selbst besser bedient. Tailcat ist ausdrücklich kein Ersatz dafür.

> Gut zu wissen

  • Die Tailcat-Adresse ist wie ein Passwort. Wer sie hat, kann sich verbinden. Also nicht posten, nicht in Git einchecken und nur über einen sicheren Weg weitergeben, etwa per Signal.
  • Bei no-auth-ssh ist die Adresse der einzige Schutz. Für mehr Sicherheit kann man mit --ssh-authorized-keys zusätzlich SSH-Schlüssel verlangen.
  • Das öffentliche Relais von Tailscale speichert Metadaten der Verbindungen. Die Inhalte bleiben verschlüsselt, aber für maximale Privatsphäre ist das Relais nicht gedacht.
  • Tailcat ist noch sehr neu (erschienen im September 2026) und kann sich noch ändern.

> In short

Tailcat is a command-line tool from Tailscale that connects two machines through an encrypted tunnel in seconds. You can use it to log in via SSH, transfer data or forward ports. It needs no account and no root privileges, and it works not just on your home network but across the internet too.

> How it works

  • On the machine you want to reach, you start Tailcat. It prints a tailcat address, a long string starting with tc.
  • You hand that address to the other machine, and Tailcat builds the tunnel with it.
  • Encryption is done with WireGuard, the same protocol Tailscale uses.
  • Where possible, the machines connect directly. If that fails, for example because of a router or firewall, traffic goes through a Tailscale relay.
  • Tailcat runs entirely as a normal program: no root, no changes to network settings or DNS.

> What you can do with it

Send text or data:

# Machine A (prints the address)
tailcat

# Machine B
echo hello | tailcat [ADDRESS]

Log in via SSH:

# Machine A
tailcat --serve=no-auth-ssh

# Machine B
tailcat ssh [ADDRESS]

Forward a port, for example a local web server:

# Machine A
tailcat --serve=8080

# Machine B
tailcat [ADDRESS] 8080

There is also a SOCKS5 proxy and an SFTP server for file transfers through the tunnel.

> Tailcat or Tailscale?

Tailcat is made for short, ad-hoc connections: quickly SSH into a machine, move a file over, expose a service for a moment. If you want to connect your devices permanently in a private network, Tailscale itself is the better fit. Tailcat is explicitly not a replacement for it.

> Good to know

  • A tailcat address is like a password. Anyone who has it can connect. So don't post it, don't commit it to Git, and only share it through a secure channel, like Signal.
  • With no-auth-ssh, the address is the only protection. For more security, you can additionally require SSH keys with --ssh-authorized-keys.
  • Tailscale's public relay keeps metadata logs of connections. The contents stay encrypted, but the relay isn't meant for maximum privacy.
  • Tailcat is still very new (released in September 2026) and may still change.
